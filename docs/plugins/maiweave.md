# MaiWeave

[项目与安装说明](https://github.com/ilworkcn/MaiWeave) · [已记录的接口版本](../../integrations/maiweave/baseline.json)

## 简介

负责日程、活动、睡眠、生活经历和主动交流。使用原版插件，在它自己的配置页或工作区设置作息、时区、模型任务和交流对象。

MaiTogether 默认读取 `get_life_status` v1，无需填写接口名称。配置示例已经允许 MaiWeave 主动分享，具体对象和频率仍在 MaiWeave 中设置。建议时区与[日期上下文插件](date-context.md)保持一致。

## 睡眠和发言

聊天思考、亲密关系、唤醒和生活循环由 MaiWeave 与 MaiBot 处理。MaiTogether 只在实际对外发送前检查生活状态：

| 公开状态 | 对外动作 |
| --- | --- |
| 清醒休闲、休息、用餐等活动 | 允许，仍检查群静音和权限 |
| 学习、工作、出行 | 暂停 |
| 睡眠，且没有有效的临时唤醒 | 暂停 |
| 接口异常、状态过期或无法确定 | 暂停 |

基础聊天频率由 MaiBot 设置；主动分享的频率由 MaiWeave 设置。发送检查不会替它们计算新的发言概率。

睡眠期间消息仍可以进入官方聊天和记忆流程，模型也可能被调用。唤醒条件按 MaiWeave 自身规则执行，与 MaiIdentity 的管理员身份不是一回事。

## 当前状态判断限制

本项目的 v1 读取规则在“按作息运行、当前无活动且无有效唤醒期限”时会暂停发送，因为已记录的接口不能确定这是否为临时唤醒后的回睡间隙。日志原因为 `sleep_state_ambiguous`，相关讨论见 [Issue #2](https://github.com/ilworkcn/MaiWeave/issues/2)。这不会阻止消息接收或 Planner 理解唤醒请求。

默认要求生活状态在 180 秒内更新。若调慢生活更新频率，再同步调整[状态有效时间](../configuration.md#生活状态和配置位置)。公开接口的活动信息也不自动意味着可以公开分享全部标题、地点或未来安排。

MaiWeave 更新较快。更换版本涉及状态 API 或唤醒逻辑时，需要重新核对接口；当前记录不是要求所有用户永久锁在该提交。维护验证方法见[维护说明](../maintenance.md)。
